# A lost webhook response can follow accepted input

In Cloud, a standalone verified `adnanh/webhook` 2.8.3 process loaded the unchanged `0a1ba30162265efda9ffacf4f304602409873d11` hook template and invoked a debug rebuild of that source. A current debug build from `a8aa82684c0f9a5c46906734239a8a59831c1860` initialized a private synthetic SQLite database and a synthetic artifact subscription; no actual service or subscription was accessed. The request carried synthetic data and a synthetic HMAC. Dispatch was disabled (`CODEX_WAKE_DEFER=1`) and no Codex delivery was attempted.

The synthetic sender sent the complete HTTP request, closed its connection before any HTTP response, and observed no HTTP status. The handler nevertheless changed the matching subscription to `ready`. Thus absence of an HTTP acknowledgement is compatible with prior durable database acceptance; it does not establish failure, final delivery, or what the real sender retries. The observed outcome covers this one artifact path, not all event kinds, all handler versions or systemd. The old executable is a rebuild, not the installed executable. This test does not verify an atomic ingress cutover.

Checksums: old debug rebuild `d57da01cdc87eee3e2231a6592282d6c4c3adc812489dbf7bf700ece42d7dde0`; current debug executable `1c97fd2f6ae019362370550451e8251880b1a90e3fb9b7bc1ce9067684f12a46`; standalone webhook `12c895f29250cbc4289ca45838235d334b39af6cf49d8e17fb43d8efed10372d`; receipt `1e679dd0c60836506899ad72d5e8f6ef51c86177531643aaa42b7a62b9aff390`; harness `20a3e301fd8b264b5cce06234fe7cbca76e1d75337dc4df32c77a0868349a093`. The harness records the specific Cloud fixture paths; it is not a portable CI test. CI for `a8aa826` passed: https://github.com/alexx-ftw/codex-wake/actions/runs/42383493505.

A durable ingress must keep a request whose downstream acknowledgement is lost in an explicitly uncertain state, not automatically resend it merely because no response arrived. Whether replay is safe depends on the identity, claim and behavior of every affected old and new route. Previously observed duplicate protection for one artifact route does not establish that for all sources. Before installing such an ingress, its own zero-loss handoff in front of the existing fixed-port listener also requires an independently demonstrated atomic switch or an upstream source that durably retains and can reconcile the affected events. Neither capability was established here.
